## 1. 무엇을 테스트하는가

Case가 `Warranty_Determination__c = 유상`(보증 미적용) & `Approval_Status__c = 승인 대기` 상태일 때, 포털 화면 우측 "보증 판정" 패널에 **승인/반려 버튼**이 나타난다. 고객이 버튼을 누르면:

- **승인** 클릭 → `Approval_Status__c = 승인`, `Approved_At__c`에 현재 시각 기록
- **반려** 클릭 → `Approval_Status__c = 반려`, `Approved_At__c`는 비워둔 채 유지

두 경우 모두 처리 후 버튼이 사라지고 "승인 상태" 텍스트가 즉시 갱신된다(재조회 없이 자동 반영됨).

Apex는 새로 만들지 않았고, 표준 `lightning/uiRecordApi`의 `updateRecord`로 Case를 직접 갱신한다. 권한세트 `CorePress_Service_Detail_Access`에서 `Approval_Status__c`/`Approved_At__c` 두 필드만 편집 가능으로 풀었고, 나머지 필드(보증 판정, 견적 금액 등)는 여전히 읽기 전용이다.

## 4. 테스트 절차

### 4-1. 화면 진입 확인

1. 위 계정으로 로그인 → 포털 홈에서 "서비스 요청" 메뉴 클릭 → 서비스 요청 목록(`service-list`)으로 이동.
2. `00001047` 행 클릭 → 서비스 요청 상세(`service-detail`)로 이동.
3. 우측 "보증 판정" 패널에서 다음이 보이는지 확인:
   - 보증 판정: **유상**
   - 유상 사유: 보증기간 만료(설치 후 26개월 경과)
   - 견적 금액: 1,850,000원
   - 승인 상태: **승인 대기**
   - **승인 / 반려 버튼 2개**가 그 아래 나란히 보임

### 4-2. 승인 플로우

1. **승인** 버튼 클릭.
2. 클릭 즉시 버튼이 비활성화(잠깐)되었다가, 성공하면:
   - 승인 상태 텍스트가 **승인**으로 바뀜
   - 승인/반려 버튼이 화면에서 사라짐
3. 내부 Salesforce(Setup이 아니라 일반 App)에서 Case `00001047` 레코드를 열어 확인:
   - `Approval_Status__c` = `승인`
   - `Approved_At__c`에 방금 클릭한 시각(UTC 기준이므로 표시 시간대 유의)이 기록돼 있는지

### 4-3. 반려 플로우 (승인 테스트 후 재사용하려면 리셋 필요)

승인 상태로 바뀌면 버튼이 사라지므로, 반려를 테스트하려면 먼저 Case를 다시 "승인 대기"로 되돌려야 한다.

**리셋 방법 (내부 Salesforce, 관리자 화면)**

1. Case `00001047` 레코드 열기 → 편집.
2. `Approval_Status__c`를 `승인 대기`로 변경, `Approved_At__c`는 비움(clear) → 저장.
3. 포털 화면으로 돌아가 새로고침하면 버튼이 다시 보임.

**반려 테스트**

1. **반려** 버튼 클릭.
2. 승인 상태 텍스트가 **반려**로 바뀌고 버튼이 사라지는지 확인.
3. 내부 Salesforce에서 Case 확인:
   - `Approval_Status__c` = `반려`
   - `Approved_At__c`는 **비어 있어야 함** (반려는 승인 시각을 기록하지 않음 — 의도된 동작)

### 4-4. 버튼이 안 보이는 경우로 상태 전환 확인

- `Warranty_Determination__c`를 `무상`으로 바꾸면 → 보증 판정 패널 자체가 축약되어 유상 사유/견적/승인 상태/버튼이 전부 안 보여야 함 (무상은 애초에 승인 대상이 아님).
- `Approval_Status__c`를 `미요청`으로 바꾸면 → 승인 상태는 텍스트로 보이지만 버튼은 안 보여야 함 (승인 대기 상태에서만 버튼 노출).
